# 副機製版速度更新 2.2.0

主機輪詢優化之後，副機製版仍會反覆啟動 Python 並載入 PDF 與中文字型。本版改由單一常駐子程序處理 `preview`、`prepare`、`cached-document`；啟動服務時先載入套件與字型。PDFium 工作始終串行；工作逾時或回覆不符時終止該子程序，本次請求不重試，下一次獨立請求重新啟動。

同一程序中，已成功通過條碼核對的製版結果最多保留 8 份、48 MiB。快取鍵包含原始 PDF 全文與所有製版選項（平台、密碼、物流號、版型、底部商品及金額）。快取只保存列印檔案位元組與製版回覆，不保存或複製工作識別碼、狀態與送印權限。外部修改先前工作的檔案也不會污染快取。程序重啟或輸入改變後重新完整核對。

`bridge.py` 原有歷史狀態與重印規則保持有效；只有原本呼叫 PDF 轉換子程序的路徑改走 `RenderClient`。Windows 紙張、203 DPI、實體列印程式與防重複送印流程未更動。

安裝需同時更新 `bridge.py`、`render_client.py`、`render_worker.py`，保留原有設定、密碼保護、jobs、originals、prepare.py 與列印程式。列印佇列及本機請求均閒置時重新啟動助手，`/health` 應回報 `2.2.0-warm-renderer`。沒有修改蝦皮 Chrome 助手，這次不需要重新載入擴充功能。

驗證：30 項測試涵蓋來源與物流綁定、舊單與送印不明狀態、缺貨號、不同金額與商品失效快取、快取容量、逾時終止、錯誤回覆及不支援列印操作。三平台實際原單的新版列印 PNG 與舊版逐檔 SHA-256 完全相同，沒有實體試印。

同機隔離製版樣本（不含網路與走紙）：蝦皮舊版 1.54 秒／新版首次 0.54 秒；MOMO 雙張 2.20 秒／1.44 秒；酷澎 1.54 秒／0.62 秒。同份內容再次製版約 0.006～0.012 秒。服務預先載入約 1.78 秒，發生於啟動時。上述為單批測試，不代表整體取單時間或所有版型的效能承諾。
