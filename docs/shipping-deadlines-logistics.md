# 包貨窗口物流分類與平台期限

未處理訂單可依全部物流、新竹物流／貨運、其他物流、物流待確認篩選，和來源平台篩選同時生效。每組依可核對的最晚出貨時間由近到遠排列，沒有可確認期限的列在其後。查詢範圍仍是畫面標示的近 3 天，不代表更早的未出貨訂單已處理。

17:00 是店內指定的新竹物流交寄提醒，並非蝦皮或其他平台的正式期限。各平台沒有期限來源時顯示待確認，不以訂單日期、配送方式或經驗天數推算。

蝦皮期限來源是 EasyStore 蝦皮通路訂單表格中明確標示的出貨期限。物流讀取助手同時核對 EasyStore 訂單 ID 和蝦皮訂單編號，只保留物流、期限與證據網址。主機加上核對時間，經原有訂單內容綁定驗證後才傳給包貨頁。API 提供的物流名稱仍優先。

只有完整年月日與有效時分才作為精確時間排序；日期沒有時分時標示日期精度，當日不以 00:00 判為逾期。今天／明天以核對當下台灣日期固定為絕對日期，畫面保留平台原文。其他無法解析的文字仍顯示，但不猜測時間。讀取失敗、訂單異動或資料超過 24 小時時不把舊資料視為最新期限。

副機的蝦皮取單小幫手本來就直接讀取該機 Chrome 的 EasyStore；訂單同步和處理紀錄仍由主機負責。包貨頁現在遇到網路錯誤或暫時性服務錯誤時，最多連續重試 5 次「查詢同一工作結果」。不重送 enqueue，不重做出貨，也不重印。此次沒有真實長時間連線或出紙測量，不能據此保證已排除所有卡頓。

## 部署

GitHub Pages 發布可更新分類、期限呈現與結果查詢重試。要開始收到蝦皮期限，主機也必須更新：

- 出貨工作台的 shipping_core.py、shipping_delivery.py、shipping_remote.py 與新增的 shipping_deadlines.py。
- 主機配送讀取助手的 reader.js，保留原 pairing.js 和擴充功能設定。
- 主機若使用本機畫面，同步更新 shipping-ui 內的 app.js、model.js、index.html、style.css。

更新主機前先完成進行中的取單／送印並停止出貨服務，備份上述檔案，再更新、重啟服務和重新載入主機配送讀取助手。副機重新整理包貨頁並讀取最新訂單。此更新不需要重建帳號、重設配對、放寬權限或公開主機服務。

主機程式與 Chrome 配送讀取助手未更新時，前端仍可使用分類與斷線重查，但期限可能繼續顯示待確認。MOMO、酷澎、官網與 LINE 尚無此版本已驗證的官方期限來源，保持待確認。
