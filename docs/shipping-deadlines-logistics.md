# 包貨窗口物流分類與平台期限

未處理訂單可依全部物流、新竹物流／貨運、其他物流、物流待確認篩選，和來源平台篩選同時生效。每組依可核對的最晚出貨時間由近到遠排列，沒有可確認期限的列在其後。查詢範圍仍是畫面標示的近 3 天，不代表更早的未出貨訂單已處理。

17:00 是店內指定的新竹物流交寄提醒，並非蝦皮或其他平台的正式期限。各平台沒有期限來源時顯示待確認，不以訂單日期、配送方式或經驗天數推算。

蝦皮期限來源是 EasyStore 蝦皮通路訂單表格中明確標示的出貨期限。副機原有「柚子樂器－蝦皮貨運單列印」擴充功能更新為 1.2.8 後，可直接讀取同一台 Chrome 已登入的 EasyStore，不必另裝程式或更新主機。讀取時同時核對 EasyStore 訂單 ID 和蝦皮訂單編號，只傳回物流、期限、核對時間與證據網址；回傳時再核對訂單內容是否異動。API 提供的物流名稱仍優先。

載入最新訂單後自動讀取，也可按「更新蝦皮物流與期限」。讀取只在小幫手建立的背景分頁進行，最多 6 頁、55 秒，完成後關閉該分頁；不動使用者原有分頁，不建立貨運單或送印。取貨運單優先，開始取單時取消背景期限讀取。未讀到的訂單維持待確認；本機快取最多沿用 5 分鐘，重新讀取失敗時舊期限標為待更新。

只有完整年月日與有效時分才作為精確時間排序；日期沒有時分時標示日期精度，當日不以 00:00 判為逾期。今天／明天以核對當下台灣日期固定為絕對日期，畫面保留平台原文。其他無法解析的文字仍顯示，但不猜測時間。讀取失敗、訂單異動或資料超過 24 小時時不把舊資料視為最新期限。

2026-11-19 現場照片確認 EasyStore 也會提供 `20-11-2026, 11:59 晚上` 格式。包貨頁新增此來源的日－月－年與上午／晚上解析，統一以台灣時間顯示「最晚出貨：2026年11月20日 23:59」。來源原文保留於提示文字，沒有時分的日期不補時分。此修正只需重新整理包貨頁，沿用小幫手 1.2.8；不必更新主機。其他來源不自行套用可能有歧義的日－月－年解析。

使用者已確認 MOMO 官方後台顯示「最晚出貨日」。現有 `normalize_momo` 尚未傳回此欄位，不能以空白認定平台沒有提供。需核對 MOMO 官方 OrderQuery 欄位或正式後台資料後另行接入；截至本次更新尚未完成，不以 `planShipDate` 或一般出貨日期推測。官方 API 文件下載位置為「商店 > 店面管理 > A202 資料下載 > API串接」（來源：https://rules.momo.com.tw/bulletin/00016/index.html）。

副機的蝦皮取單小幫手本來就直接讀取該機 Chrome 的 EasyStore；訂單同步和處理紀錄仍由主機負責。包貨頁現在遇到網路錯誤或暫時性服務錯誤時，最多連續重試 5 次「查詢同一工作結果」。不重送 enqueue，不重做出貨，也不重印。此次沒有真實長時間連線或出紙測量，不能據此保證已排除所有卡頓。

## 部署

一般副機使用方式：

1. 在 Chrome 擴充功能頁重新載入桌面原有小幫手，確認版本為 1.2.8。
2. 重新整理包貨頁，並保持這台 Chrome 已登入 EasyStore。

GitHub Pages 已包含分類、期限呈現、本機小幫手連接與結果查詢重試。這條副機讀取路徑不需要另外更新主機；訂單同步和處理紀錄仍由主機負責。

另保留主機配送讀取助手的可選路徑。只有要使用主機取得期限時，才需一起更新：

- 出貨工作台的 shipping_core.py、shipping_delivery.py、shipping_remote.py 與新增的 shipping_deadlines.py。
- 主機配送讀取助手的 reader.js，保留原 pairing.js 和擴充功能設定。
- 主機若使用本機畫面，同步更新 shipping-ui 內的 app.js、model.js、index.html、style.css。

更新主機前先完成進行中的取單／送印並停止出貨服務，備份上述檔案，再更新、重啟服務和重新載入主機配送讀取助手。副機重新整理包貨頁並讀取最新訂單。此更新不需要重建帳號、重設配對、放寬權限或公開主機服務。

副機小幫手尚未重新載入時，包貨頁會提示更新，仍可使用分類與斷線重查。MOMO、酷澎、官網與 LINE 尚無此版本已驗證的官方期限來源，保持待確認。尚未完成使用者實際 Chrome 重新載入後的現場驗證，不能宣稱所有訂單都已取得期限或列印速度已改善。
